# 邮件队列

## 结构与事务

`mail_outbox` 是共享基础表，业务模块在自身事务内写入；队列写入失败则整个业务事务回滚。账户模块在 `notifications.go` 集中构造验证邮件和安全通知，经 store 校验后入队，不依赖发送器。`modules/mailoutbox` 管理消费状态，`app/worker` 装配数据库和 `platform/mail.Sender`，后续供应商实现沿用这个接口。

空数据库先应用完整基线 `00001_init.sql`，再启动 API 和 Worker。Worker 必须设置 `DATABASE_URL`，`DB_MAX_CONNS` 默认 5，`MAIL_POLL_INTERVAL` 默认 1s。当前发送器为日志 mock，返回成功后队列标记 sent；这里的 sent 表示发送器接受请求，不代表真实收件箱投递。

## 领取与重试

消费策略常量集中在 `internal/modules/mailoutbox/delivery.go`。最大投递次数、租约时长和清理批量作为具名参数传入 SQL，领取、重试和终态清理共用同一上限。

- 每次用 `FOR UPDATE SKIP LOCKED` 原子领取一封邮件，最多尝试 5 次；每个 Worker 串行处理，可多副本并行。
- 租约 60 秒，每次领取生成新 UUID；完成或重试必须匹配租约且尚未过期，旧消费者不能覆盖新状态。
- 单次发送最多 10 秒，并受邮件有效期和进程取消约束。发送器必须响应 context，停机后状态落库最多等待 5 秒。
- 失败按 15、30、60、120 秒退避，额外加入 0–9 秒抖动。仅保存固定错误码，不保存供应商原始响应。
- 崩溃后由租约过期恢复。达到 5 次或超过有效期进入 failed；验证邮件有效期等于对应挑战有效期，安全通知默认 24 小时。
- 过期扫描每次最多处理 100 行。成功或最终失败清空收件人、标题、正文；终态元数据保留，无自动历史记录删除任务。

## 幂等与内容

语义为至少一次：供应商接受请求后，若进程未能记录成功，租约恢复后可能重复投递。适配支持幂等键的供应商时始终传入稳定的 `Message.ID`；不支持的供应商不能保证恰好一次。

按当前设计，待发邮件明文落库，验证链接包含可使用的挑战令牌；认证验证表仍只保存摘要。禁止将邮件载荷写入日志或审计，数据库和备份需要限制访问。挑战消费、认证版本及有效期仍由账户模块校验；提前失效的链接不能完成验证。终态清除在线载荷不等于删除历史备份。

注册和密码恢复的 202 是统一受理响应，不保证每次都生成邮件；需要生成的邮件与业务变更同事务入队，不等待供应商发送。发送器故障不会回滚已提交的账户操作。监控 pending 最老等待时间、failed 数量及 Worker 错误日志；永久失败的验证邮件由用户重新发起业务流程，不自动恢复已过期消息。

失败日志包含固定的 `stage` 与安全的 `reason_code`，数据库错误可附带 `sqlstate`。领取到邮件后的发送、回写和租约错误另带 `message_id`、`attempt`：`expire` 表示清理过期邮件，`claim` 表示领取，`send` 表示供应商调用，`complete` / `retry` 表示结果回写，`confirm_lease` 表示回写时租约已失效。供应商响应、数据库错误原文及邮件载荷不进入日志。发送取消、超时和其他依赖故障可通过分类区分；进程取消后若结果回写失败，仍记录该故障并由租约到期恢复。

集成测试通过公开的 `ProcessOne` 入口与可控制时序的发送器验证消费者竞争、发送取消后的状态回写、回写失败后的租约恢复、旧消费者回写被拒绝及邮件有效期。供应商幂等键在恢复重试中保持为同一个邮件 ID。

## 正文格式

发送接口统一使用 `Message.HTML`，`mail_outbox.body` 保存 HTML 正文，供应商适配器按 `text/html` 投递。账户验证链接与安全通知中的动态内容在组装 HTML 时转义，日志 mock 不输出 HTML 内容。
